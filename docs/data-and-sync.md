# Данные и синхронизация между устройствами

Весь прогресс — обычные файлы в каталоге данных (`$LEARN_HOME`, по умолчанию `~/learning`):

```
~/learning/
  config.json             язык, часовой пояс
  profile.md              ваш профиль (агент читает в начале каждого занятия и дополняет)
  plans/<slug>/
    plan.json             план: результаты, модули, уроки
    progress.json         результаты уроков, карточки повторения, события
    PLAN.md               читаемая копия с чекбоксами и прогресс-баром (генерируется)
```

Код (`~/learn`) и данные (`~/learning`) — **разные репозитории**: код публичный, ваш прогресс — приватный.

Защита от случайной публикации (форк публичный):

- по умолчанию данные лежат **вне** клона кода (`~/learning`), так что `git add` в клоне их просто не видит;
- если всё же положить данные внутрь клона (`learning/`, `data/`, `plans/`, `profile.md`, `progress.json` …), их перекрывает `.gitignore`;
- `learn sync` отказывается работать, если каталог данных находится внутри репозитория с кодом, а `learn init` в этом случае выводит предупреждение;
- не коммитьте `.env` с токеном Telegram — он тоже в `.gitignore`.

## Синхронизация через приватный git

Один раз:

```bash
cd ~/learning
git init -b main
git remote add origin git@github.com:<вы>/my-learning.git   # создайте ПРИВАТНЫЙ репозиторий
learn sync
```

На втором устройстве: `git clone <тот же репозиторий> ~/learning`.

Дальше `learn sync` коммитит изменения, делает `pull --rebase` и `push`. Скиллы вызывают его в начале и конце занятия. Если оба устройства изменили прогресс одновременно, команда откатывает rebase, ничего не теряет и просит разрешить конфликт вручную — поэтому не учитесь с двух устройств параллельно.

## Вместо git: один сервер на VPS

Если нужна работа с нескольких устройств **одновременно** (или просто не хочется думать о слиянии), держите данные только на VPS и ходите в них через MCP/REST: [remote-server.md](remote-server.md). Источник правды один, изменения видны сразу везде, конфликтов нет. Приватный git при этом остаётся удобным способом делать резервные копии (`learn sync` в cron на сервере).

## Просмотр на телефоне

`PLAN.md` — обычный Markdown с чекбоксами. Каталог `~/learning` можно открыть как хранилище Obsidian (мобильное приложение + любая синхронизация или тот же git) и смотреть прогресс как «живой» план.

## Резервная копия и перенос

Каталог самодостаточен: скопируйте его — и прогресс переехал. `learn` не хранит ничего вне `$LEARN_HOME`.
